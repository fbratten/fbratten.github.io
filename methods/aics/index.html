AICS

Atomic Instruction Communication Standard working expansion

AICS represents human–AI work as one versioned semantic contract. Conversation, repository, execution and handover views remain projections of that contract. Instructions, requirements, assumptions, decisions, evidence and verifications stay separately addressable.

          09

          Scientific interpretation and boundaries

          Stable IDs, versioning, one contract, phase gates and reciprocal verification links should make drift and unauthorized action easier to detect. This remains a mechanism hypothesis.

          Problem

          Chat, repository and agent interpretations drift. Requirements disappear into prose and confidence replaces measured verification.

          Evaluation

          Measure requirement loss, unauthorized actions, blockers, handover drift, verification coverage, rework and closure defects.

          Non-claims

          • AICS 0.2 and its expanded name remain experimental.
          • Core validity does not imply executability or repository write permission.
          • Profile reports are not cryptographic attestations.
          • Self-hosting is not self-approval.
          • Distributed locking, signing, hash serialization, ORBIT mapping, MCP and automatic natural-language changesets remain deferred.
          • These browser labs are not the validator, changeset executor or renderer.
