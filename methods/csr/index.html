CSR

Capability Surface Reconciliation establishes where a named capability or stated need exists, in which realization state, how its representations relate, what covers which part of the need, and the smallest sufficient intervention before something new is built or installed.

Working design baseline

Question

For a named capability or stated need: what is each representation, where does it exist, is it merely documented or actually implemented/adopted, and what change - if any - is minimally sufficient?

Core model

named capability / need
→ identity + surface inventory
→ realization state
→ representation relationships
→ coverage map
→ smallest sufficient intervention

Boundaries

documented != runtime available
implemented != installed
installed != authorized
surface != capability identity
reconciliation != orchestration

Composition

CSR composes with SORR for semantic resolution, ORBIT for orientation, Capability-Gap Reconnaissance for absence discipline, GDSA for relevance/activation and CARD/POINTER for durable representation and routing.

Current maturity

The governed source currently records a working design baseline. The skill family is not represented here as already implemented.
