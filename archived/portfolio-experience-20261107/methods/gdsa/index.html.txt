<div class="fb-local-context "><strong>GDSA</strong></div><main id="main"><section class="hero"><span class="eyebrow">Discoverability, surfacing + bounded activation</span><h1>GDSA</h1><p class="lead">GDSA governs the path from durable existence to proportionate discoverability, routing, context-sensitive surfacing, relevance recognition, action-class-scoped authorized use, verified outcome and durable learning.</p></section><section class="grid"><article class="panel"><h2>Problem</h2><p>Documented capabilities and knowledge can become operationally invisible. The opposite failure is equally dangerous: finding or surfacing something is treated as permission and ability to use it in every possible way.</p></article><article class="panel"><h2>Lifecycle</h2><pre>durable
-> discoverable
-> routable
-> surfaced
-> relevant
-> activation candidate
-> authorized for action class
-> used
-> verified
-> learned</pre></article><article class="panel"><h2>Protections</h2><p class="boundary">durable != discoverable<br>surfaced != relevant<br>relevant != authorized<br>authorized != executed<br>execution != verified outcome</p></article><article class="panel"><h2>Composition</h2><p>SRCB can establish a bounded context model before GDSA routes deeper. ORBIT and CARD/POINTER support orientation and routing, while Dialogue Lifecycle keeps relevance, decision, authority and execution gates distinct.</p></article><article class="panel wide"><h2>Scope</h2><p>GDSA governs discoverability, relevance and bounded activation semantics. It is not a storage backend, scheduler or authorization provider, and it keeps availability, authorization, execution and verified outcome as separate states.</p></article></section>
<section class="cbe-composition" id="cbe-example" aria-labelledby="cbe-example-title"><span class="cbe-kicker">Composition exercise</span><h2 id="cbe-example-title">Apply this method to CBE and CBE-IX</h2><p>Surface CBE when a defined capability needs boundary analysis and CBE-IX when repeated expansion is justified. Relevance selects an analysis route; it does not authorize implementation of the resulting KEEP responsibilities or invocation of delegated peers.</p><p><a href="../cbe/#lab">Classify an ingestion candidate</a> / <a href="../cbe-ix/#lab">Inspect its iterative expansion</a> / <a href="../solutions/#bounded-capability-design">Explore the composed solution</a></p></section>
