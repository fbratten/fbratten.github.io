<div class="fb-local-context "><strong>Capability-Gap Reconnaissance</strong></div><main id="main"><section class="hero"><span class="eyebrow">Reuse-before-create discovery gate</span><h1>Capability-Gap Reconnaissance</h1><p class="lead">A conditional method for checking what the ecosystem already contains before an observation becomes new implementation work.</p></section><section class="grid"><article class="panel"><h2>Problem</h2><p>Absence from one file, branch, repository, device or current context does not prove a capability is absent. Premature creation produces duplication, fragmented authority and avoidable maintenance.</p></article><article class="panel"><h2>Flow</h2><pre>Observation / signal
-> capability-gap gate when triggered
-> inspect repos, projects, branches, PRs, workflows and indexes
-> REUSE | ADAPT | CONTINUE | CREATE | NO ACTION</pre></article><article class="panel"><h2>Boundary</h2><p class="boundary">not found here != does not exist<br>main != complete historical evidence<br>discovery != authority<br>recommendation != execution</p></article><article class="panel"><h2>Use when</h2><p>Use it when a signal appears to imply a reusable capability, unfinished implementation, overlapping work or a potentially reusable mechanism. It is a conditional gate inside a broader observation flow, not a separate note type or automatic build instruction.</p></article><article class="panel wide"><h2>Authority and scope</h2><p>This public page projects the method's purpose and invariants without exposing private estate details. Claims about what exists in a current estate still require fresh evidence from the relevant repositories, branches, runtime surfaces and indexes.</p></article></section>
<section class="cbe-composition" id="cbe-example" aria-labelledby="cbe-example-title"><span class="cbe-kicker">Composition exercise</span><h2 id="cbe-example-title">Apply this method to CBE and CBE-IX</h2><p>First look for an existing ingestion capability and its peers. Once a genuine internal gap in an identified target is established, CBE classifies the proposed extension. CBE-IX is useful if that accepted extension exposes further gaps. Neither variant is evidence that a new capability must be built.</p><p><a href="../cbe/#lab">Classify an ingestion candidate</a> / <a href="../cbe-ix/#lab">Inspect its iterative expansion</a> / <a href="../solutions/#bounded-capability-design">Explore the composed solution</a></p></section>
</main><div class="fb-context-footer">Reuse reconnaissance reduces false novelty while keeping discovery separate from authority and execution.</div><!-- FB:FOOTER -->
